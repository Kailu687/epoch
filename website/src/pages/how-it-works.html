How it works

Five steps, one honest evaluation

Each step maps to a screen in the desktop application. Steps marked partial or planned are not yet complete.

  1. 1. Import your data

    Select a CSV file. The engine detects the delimiter and encoding, reads a bounded preview and computes a content hash so the dataset can be identified later. CSV works from source Excel, Parquet, images, audio planned

  2. 2. Inspect and validate

    Column types, missing values, constant and ID-like columns, duplicate rows, class imbalance and suspected target leakage are reported. Errors block training; warnings need your attention but do not.

  3. 3. Configure the learning task

    Choose the target column. The engine suggests classification or regression and a split protocol and explains why. You can override it. Seeds are fixed so the split can be reproduced.

  4. 4. Train and evaluate models

    Candidates run in a separate worker process. A baseline is always trained first, so you can see whether any model is actually useful. Selection uses validation data. The test set is evaluated once for the selected model, and that use is recorded.

  5. 5. Export and deploy

    The export bundle contains the fitted pipeline, input schema, label mapping, configuration, metrics and a Python example. Bundles are checksummed; load only bundles you trust.

Why the evaluation protocol matters

Preprocessing

Imputation, scaling and encoding are fit on training rows only, inside the pipeline.

Metrics

Classification shows macro-F1, balanced accuracy and a confusion matrix, not accuracy alone. Regression shows MAE, RMSE and R².

Splits

Stratified for classification. Group-aware and temporal splits are planned and the interface will warn when a random split looks unsafe.
